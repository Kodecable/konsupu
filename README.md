# Konsupu

Konsupu 是一个目前失败的符号-神经网络实验。Konsupu 尝试使用 LLM 驱动将自然语言翻译到符号域，并使用 LLM Agent 编写符号域的处理程序以实现无限上下文和稳定抗提示词注入的人工智能解决方案。

详细设计见 `doc/`。

## 成功与失败部分

目前未能使得 LLM 在可控的成本内稳定产出正确的符号逻辑。详情见下文。

LLM Agent 在编写符号域程序上表现出了足够的智能，这可能是因为其本质就是普通计算机程序。

## 未能使得 LLM 在可控的成本内稳定产出正确的符号逻辑

TLDR: 模型内部有类似句法结构的存在（[见此](https://www.nature.com/articles/s41562-025-02297-0)），能正确对自然语言回答，不代表它能够稳定输出完整句法树。

近年的多篇文章指出（[1](https://aclanthology.org/2024.acl-long.384/) [2](https://jlcl.org/article/view/285)），LLM 具有一定符号域程序构建能力。「那么在 LLM 经过多轮发展过后的今天，这项能力或许已经足够完备？」抱着这样的想法，进行了实验。

实验主要使用了 deepseek-v4.1-flash, mimo-2.6-flash, mimo-2.6-pro 模型。大部分实验过程和结果数据位于 `doc/` 下的压缩包内。

### 初步实验

在完成基础脚手架后，以伊索寓言问答为示例需求和实验对象，指导 LLM Agent 参与设计了一套基于 JS 的符号逻辑系统。见 `doc/` 下的 foundation 和 commons。不直接采取 AMR/UMR 是因为其依赖 PropBank“神谕”，且不便于符号域求解实现。

在完整实现求解器前，对 LLM 驱动的符号翻译进行了简单的实验。由于当时尚无完整的求解器，对 LLM 驱动结果的评估整体过于乐观。

值得一提的是，在实现中，考虑到可扩展性，LLM 翻译符号逻辑是使用类似 agent loop 的模式多次在 JS runtime 内 eval 探索知识库并逐步构造符号表达并验证，仿照了 coding agent 的模式。

设计途中的多次草案与原型实现见 `doc/aesop-before-commons.zip`。完整实现前后的实验见 `doc/aesop-commons.zip`。

实现完毕后的实验结果整体不佳。在针对性的 prompt 工程下，基础单句故事和问题能正确作答。但是略长一点的一篇完整伊索寓言要么多次重试失败甚至无法改进（关闭思考时），或在 JS runtime 内长思考漫游不进行实际回答（启用思考时），同时会丢弃部分语义：有的是一开始就丢失了，有的是为了通过检验器而主动丢弃上一轮已知的语义。

### 对符号翻译的仔细实验

实验中设计的符号系统为了精确求解，采取了抽象基类 + 可扩展的明确子类的设计方法，同时实现了类似 Python 的内置 `help` 系统，方便 LLM Agent 翻译时仔细确定语义。但这似乎导致了模型的理解困难和漫游。因此尝试使用 AMR 让模型进行简单的单轮可重试推导。结果仍不理想，机器检查和重试可以消除绝大部分语法错误和部分语义错误，但难以消除频繁出现语义丢失等错误。

同时试探性地进行了多种实验：开启思考、将文章分割为单句、为单句附带少量上下文。开启思考对语法有一定效果，但对语义错误几乎没有改变，同时 token 消耗大幅增加（19k -> 167k）。正如 LLM 架构在理论上所预期的，后两种做法对结果没有显著影响。

采用 prompt 工程针对性地处理后，语义错误率明显降低但仍然较高。值得一提的是，参数量较大的模型的语义错误明显较少。

考虑到 LLM 在使用自然语言回答时，能稳定地正确回答相关错误项，开始怀疑是否通用 LLM 对 AMR 学习较少/对偏离自然语言的表达无法正确输出。因此又使用简单设计的有限符号化英语和成分句法树为目标进行测试，令人意外的是，语义错误率基本没有下降。

实验数据见 `doc/amr-cnl-spt-trial.zip`

实验到此没有较好的下一步可行方案，停止。

### 疑惑

1. 模型参数量提升对语义错误数量下降有明显的正面效果。小激活 MoE 似乎并不适合此类用途。但 AMR 专用神经网络参数量并没有多高。似乎应该怀疑是 LLM 对此方面训练较少，泛化能力不足？
2. 似乎符号化表达无论多接近自然语言，终究本质与自然语言不同，在没有 prompt 工程的前提下基底错误率比较接近？
3. 开启思考对语义错误率帮助较少？

## 附：部分数据汇总

判定标准：ok 为意思一致；minor 为写法有问题但原句事实都还在；major 为事实被写丢、写反或写成别的。除 held59 外均为单人非盲评。

### dev50：同一批 50 个单句（deepseek-v4.1-flash 关思考，除非另注）

| # | 目标表示 | 模型 / 设置 | ok | minor | major | major 率 | 机器检查通过 |
|---|---|---|---|---|---|---|---|
| 1 | AMR | v2 提示，无重试 | 19 | 20 | 11 | 22% | 42/50 |
| 2 | AMR | mimo-v2.6-pro，v2 提示，无重试 | 27 | 17 | 6 | 12% | 46/50 |
| 3 | AMR | v3 提示 + 检查重试（≤3 次） | 25 | 19 | 6 | 12% | 49/50 |
| 4 | CNL | 重试 | 8 | 27 | 15 | 30% | 45/50 |
| 5 | 成分句法树（PTB） | 无重试 | 20 | 12 | 18 | 36% | 34/50 |

### held59：调规则时没看过的另外 59 句（AMR，盲评）

| 设置 | ok | minor | major | major 率 |
|---|---|---|---|---|
| v2 无重试 | 20 | 31 | 8 | 14% |
| v3 + 重试 | 29 | 24 | 6 | 10% |

逐句配对：v3 更好 19、更差 11、相同 29，符号检验双侧 p≈0.20，不显著。

### 成本与消融（AMR）

| 做法 | 对比基线 | 结果 |
|---|---|---|
| 开思考 | 关思考 | 整篇故事任务 completion token 约 16.7 万对 1.9 万；10 个长句上约 5.0 万对 0.19 万，硬问题均为 7/10，耗时约 20 倍 |
| 说明书 + 示例 | 最简提示 | 机器硬问题 25/50 → 10/50，人工抽查中语义错误没有明显减少 |
| 带前后各一句上下文 | 无上下文 | 硬问题 10/15 对 5/15，代词消解无变化 |
| 检查 + 重试 | 无重试 | token 约 +41%，major 8 → 6 |
| 自然语言问答（不符号化） | — | 15/15 答对；题目为人工拟定判定，每句仅一问 |
